Python 공식 문서와 VS Code 공식 문서를 한 장으로

활성화는 편의, 실행은 경로

활성화가 하는 일
가상환경의 실행 폴더를 PATH 맨 앞에 끼워 넣는다. 그래서 그냥 python이라고 쳐도 venv의 파이썬이 잡힌다. VIRTUAL_ENV와 프롬프트 표시는 그때 같이 생긴다.
Python 문서: activate는 그 디렉터리를 PATH 앞에 붙인다
활성화는 필수가 아니다
venv 안의 파이썬을 전체 경로로 지정해 실행하면 활성화 없이도 그 환경으로 돈다. 표시가 없는 것은 고장이 아니라, 활성화 단계를 건너뛴 흔적이다.
Python 문서: "굳이 활성화할 필요는 없다. 전체 경로를 지정하면 된다"
VS Code는 선택된 환경으로 돈다
실행·디버깅·IntelliSense 모두 선택된 인터프리터를 쓴다. 디버깅만 다른 파이썬으로 돌리려면 launch.json의 python을 지정한다.
VS Code 문서: "기본적으로 디버거는 선택된 환경을 쓴다"
판별은 sys로 한다
sys.prefix != sys.base_prefix가 True면 가상환경이다. VIRTUAL_ENV는 비어 있어도 가상환경일 수 있어서 판별 기준이 못 된다.
Python 문서: "VIRTUAL_ENV에 의존할 수 없다"
"(.venv)가 안 보인다"는 "venv를 안 쓴다"가 아니다 — 실행한 파이썬의 경로를 찍어 보면 끝난다
