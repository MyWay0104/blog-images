"어느 함수가 더 좋은가"가 아니라 "무효화 신호가 어디서 오나"

신호가 오는 곳이 함수를 정한다

① 관리자 화면에서 저장
같은 서버 안의 Server Action
updateTag('posts')
저장한 사람이 바로 자기 글을 봐야 한다 (read-your-own-writes). 즉시 만료.
공식 문서: Server Action 안에서만 쓸 수 있다
② 바깥에서 알려 옴
웹훅·외부 자동화 → Route Handler
revalidateTag('posts', 'max')
옛 목록을 잠깐 더 보여 줘도 된다면 'max'. 즉시 비워야 하면 { expire: 0 }. 호출하는 쪽이 비밀번호를 들고 온다.
공식 문서: Route Handler에서는 updateTag를 쓸 수 없다
③ 아무도 알려 주지 않음
시간이 지나면 알아서
cacheLife('hours')
신호가 없으면 프로필의 revalidate 주기가 유일한 갱신 수단. 글이 뜸한 블로그면 'days'나 'max'도 된다.
공식 문서: default 프로필은 stale 5분 · revalidate 15분 · expire 없음
REVALIDATE_SECRET은 ②의 문지기다 — 아무나 /api/revalidate를 두드려 캐시를 비우지 못하게 하는 비밀번호이지, 새 글을 담아 두는 공간이 아니다. ①처럼 서버 안에서 updateTag를 부르면 바깥에서 비밀값을 넣을 일 자체가 없을 수 있다
