Next.js 16 공식 문서 네 쪽을 한 장으로

선언 · 수명 · 이름표 · 무효화

'use cache'는 선언이다
함수·컴포넌트·파일 맨 위에 적으면 그 결과가 캐시 대상이 된다. cacheComponents: true를 켜야 하고, 캐시되는 함수는 async여야 한다.
아무것도 안 적으면 default 프로필: stale 5분 · revalidate 15분 · expire 없음
cacheLife는 시간, cacheTag는 이름표
cacheLife('max')는 "시간으로는 거의 안 바뀐다"는 선언, cacheTag('posts')는 나중에 이 묶음만 골라 무효화하려고 붙이는 이름표다. 둘은 서로 다른 축이다.
같은 태그를 여러 함수에 붙이면 한 번에 같이 무효화된다
revalidateTag vs updateTag
revalidateTag(tag, 'max')는 오래됐다고 표시만 하고, 다음 요청에는 옛것을 주면서 뒤에서 새로 만든다. updateTag(tag)는 즉시 만료라서 쓴 사람이 바로 본다 — 단, Server Action 안에서만.
즉시 비워야 하는데 Server Action이 아니면 revalidateTag(tag, { expire: 0 })
갱신은 요청이 촉발한다
revalidateTag를 불렀다고 그 자리에서 다시 만들지 않는다. 태그를 쓰는 페이지가 방문될 때 갱신된다. 인자 하나짜리 revalidateTag(tag)는 deprecated.
그래서 "불렀는데 왜 아직 옛 글이지?"는 버그가 아니라 설계대로일 수 있다
